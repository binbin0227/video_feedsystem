# 视频详情接口性能测试结果

## 1. 测试目标

对比视频详情接口在以下两种数据读取方式下的性能表现：

1. Redis 视频详情缓存命中
2. 跳过 Redis，每次直接查询 MySQL

## 2. 测试配置

- 压测工具：k6
- 并发虚拟用户数：100 VUs
- 单轮测试时间：60 秒
- 每种方案测试轮数：3 轮
- 请求接口：视频详情查询接口
- 请求数据：固定且真实存在的视频 ID
- 请求模式：100 个虚拟用户持续循环发送请求
- 成功条件：HTTP 状态码为 200
- Redis 测试场景：缓存已提前预热
- MySQL 测试场景：详情接口跳过 Redis，直接查询 MySQL

## 6. 结果分析

### 6.1 吞吐量

Redis 缓存命中场景三轮 RPS 分别为：

- 30,788.67
- 31,243.11
- 31,666.05

三轮结果较为接近，中位数为 31,243.11 RPS。

直接查询 MySQL 场景三轮 RPS 分别为：

- 946.69
- 1,072.05
- 1,001.41

中位数为 1,001.41 RPS。

在相同的 100 VUs 和 60 秒测试条件下，Redis 缓存命中场景处理的请求数量明显高于直接查询 MySQL 场景。

### 6.2 响应延迟

Redis 场景的平均延迟稳定在 3.09～3.18 ms，P95 延迟稳定在 4.73～4.89 ms。

直接查询 MySQL 场景的平均延迟为 93.20～105.56 ms，整体 P95 延迟为 324.67～358.83 ms，最大延迟达到 3.81～4.47 秒。

结果显示，直接查询 MySQL 场景不仅平均延迟更高，尾部请求延迟也更加明显。

### 6.3 稳定性

Redis 场景三轮累计完成 5,622,102 次请求，所有检查均成功，请求错误率为 0%。

直接查询 MySQL 场景三轮累计完成 181,240 次请求，其中：

- 成功请求：114,574
- 失败请求：66,666
- 综合错误率：36.78%

在本次 100 VUs 持续压力下，直接查询 MySQL 场景出现了较高比例的非 200 响应。

### 6.4 测试波动

Redis 三轮测试结果较为稳定：

- 最低 RPS：30,788.67
- 最高 RPS：31,666.05
- 最大差值：877.38 RPS
- 相对中位数波动约为 2.81%

Redis 的 P95 最大差值只有 0.16 ms。

MySQL 三轮测试中：

- RPS 范围：946.69～1,072.05
- P95 范围：324.67～358.83 ms
- 错误率范围：34.78%～38.91%

三轮均出现相似的高延迟和高错误率现象。

## 7. 结论

在本次本地环境、100 VUs、持续 60 秒的测试条件下：

- Redis 缓存命中场景的三轮中位数为 31,243.11 RPS。
- Redis 缓存命中场景的 P95 延迟为 4.80 ms。
- Redis 缓存命中场景三轮错误率均为 0%。
- 直接查询 MySQL 场景的三轮中位数为 1,001.41 RPS。
- 直接查询 MySQL 场景的整体 P95 延迟为 332.41 ms。
- 直接查询 MySQL 场景的三轮综合错误率为 36.78%。

在本次测试条件下，Redis 缓存命中方案在吞吐量、响应延迟和请求成功率三个指标上均优于直接查询 MySQL 方案。

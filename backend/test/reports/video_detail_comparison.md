## 结果对比

以下采用三轮结果的中位数：

| 指标 | 直接查询 MySQL | Redis 缓存命中 | 变化 |
|---|---:|---:|---:|
| RPS | 1,626.39 | 6,356.67 | 提升 290.85% |
| 平均延迟 | 3.02 ms | 0.751 ms | 降低 75.14% |
| 中位延迟 | 2.66 ms | 0.547 ms | 降低 79.45% |
| P95 延迟 | 5.28 ms | 1.08 ms | 降低 79.55% |
| 错误率 | 0% | 0% | 均无错误 |

Redis 缓存命中场景的吞吐量约为直接查询 MySQL 的 3.91 倍。

## 结论

在相同的 5 VUs、持续 60 秒且错误率均为 0% 的测试条件下：

- Redis 缓存命中场景达到约 6,356.67 RPS。
- 直接查询 MySQL 场景达到约 1,626.39 RPS。
- Redis 缓存使接口吞吐量提升约 290.85%。
- 平均响应时间从 3.02 ms 降低至 0.751 ms。
- P95 响应时间从 5.28 ms 降低至 1.08 ms。
- 两种场景三轮测试的请求错误率均为 0%。

测试结果表明，视频详情缓存能够显著减少数据库访问开销，提高接口吞吐量并降低响应延迟。
